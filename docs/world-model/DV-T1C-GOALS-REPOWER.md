## §N — THE EX-ANTE POOLING ARITHMETIC (shown BEFORE any battery ran)

Sizing to **either** parent's point alone would be choosing which of two compatible measurements to
believe. #253.1 therefore orders the N sized to their **inverse-variance (fixed-effect)
combination**. Every input is **read from a committed artifact** by the probe, never typed.

**The inputs** — the same field in both artifacts,
`preRegisteredPrimary.allArms.dvTruthP.goalsBandLimb.goalsVsAnchor`:

| study | clusters | point | 95 % CI |
| --- | ---: | ---: | --- |
| **DV-T1** (#251) | 283 | +0.243816 | [0.045936, 0.420495] |
| **DV-T1b** (#252) | 643 | +0.040435 | [−0.083981, 0.167963] |

**The arithmetic, in seven steps:**

```text
1  se_i        = ((upper_i − lower_i)/2) / z.975
     T1        = 0.1872795  / 1.959963985                        = 0.095552521
     T1b       = 0.125972   / 1.959963985                        = 0.064272610
2  w_i         = 1 / se_i²
     T1        = 109.525615        T1b = 242.073993     Σw        = 351.599607
3  pooledPoint = Σ(w_i · point_i) / Σw_i                          = 0.103789533
4  pooledSe    = 1 / sqrt(Σw_i)                                   = 0.053330519
     (pooled 95 % CI [−0.000736363, 0.208315430] — REPORTED CONTEXT, adjudicated nowhere)
5  se_required = |pooledPoint| / (z.975 + z.80)
              = 0.103789533 / 2.801585                            = 0.037046717
6  N_raw       = ceil( 643 · (0.064272610 / 0.037046717)² )       = ceil(1935.37) = 1936   *(intermediate corrected of record #254.3 — the shipped "1935.62" was a hand-typed slip; the ceiling and N* are unchanged)*
7  N*          = min(N_raw, ledger room 2900)                     = 1936      (roomBinds = false)
```

Step 1 recovers each bootstrap SE from a 2.5/97.5 percentile paired-cluster interval. Step 5 is the
standard 80 %-power identity at 95 % two-sided — the same `(z.975 + z.80)` this family's N rule has
always used. Step 6 uses the fact that a **paired cluster** bootstrap's SE scales as `1/√N` in the
number of **clusters** (#20: cluster = match seed), scaling from **DV-T1b's OWN paired SE on this
same column at its 643 clusters** (#253.1's own instruction).

**N\* = 1936.** Ledger room is **2900** and it does **not** bind, so the pooling rule's own N runs;
the MDE actually bought at N\* is **0.103772572** — the pooled point itself, which is the point.
⭐ Had the room bound, #253.1's instruction is explicit and the probe implements it: **run the room
and DECLARE `mdeBoughtAtNStar`**, never quietly re-cut the target.

⚠ **WHY THE SCALING SE IS T1b's AND NOT THE POOLED ONE, DECLARED.** The pooled SE is the precision
of **two batteries combined** and is not available to one new battery; what a new battery of N
clusters will have is **this instrument's own per-cluster variance**, and DV-T1b is its most recent
committed estimate on this exact column, world and pair of arms. Different seeds, so it is an
**assumption** — and the probe prints the **realised** CI half-width beside the **ex-ante expected**
one (**0.072598364**) so a reader can see whether it held.

⚠ **AND WHAT THIS RULE DOES NOT CLAIM.** Resolving the pooled point is **not** the pooled point
being real, and a battery sized to it can still come back UNRESOLVED. That is #253.1's third route,
and the third route is the commander's.

**G-N** is the gate: the frozen literal `N_FROZEN = 1936` must equal the derivation, the moments
must come from the artifacts, and in FULL mode the battery must actually have **run at** N\* — a
battery that quietly ran a different N reds the gate rather than publishing a smaller MDE as if it

## §DEV — how this battery actually got run (the resume history, honestly)

The battery was launched harness-tracked at full N and **killed twice by the host's background
task cap**, at pass 1 seed 1336/1936 and at pass 2 seed 731/1936. Both deaths were confirmed on
**two** independent signals before anything was touched (#250.1's liveness watch): zero live probe
processes, and a checkpoint file that had stopped growing. Each time the run was **resumed from
`/tmp/dv-t1c-checkpoint.jsonl`** and the resume was **accepted with zero discarded records** —
1336 units restored the first time, 2667 (1936 pass-1 + 731 pass-2) the second. The envelope
records the final split: **restoredPass1 1936 / computedPass1 0 · restoredPass2 731 /
computedPass2 1205**.

⭐ **This changes nothing about the evidence, by construction.** Nothing pooled is checkpointed —
only per-(pass, seed) arm rows, each with its own sha and an encode round-trip check — and every
summary, contrast, gate, digest and `resultSha256` is recomputed from the union on the final
process. **X-DET still double-ran the whole core on that process** and the two hashed bodies are
byte-identical (`gates.xDet.pass: true`). The checkpoint is /tmp scratch, read by no gate and never
committed.

⭐ **Of record for the next long battery**: a ~3 h run does not fit inside this host's background
task lifetime, so the #207 checkpoint is not a nicety here — it is the only thing that makes a
battery of this length runnable at all. State the checkpoint path in the stage doc (this one does,
in §GATES) and make resume byte-identical by construction, not by inspection.

⚠ **One number worth the commander's eye, stated as the row it is and nothing more**: the ex-ante
variance assumption **held** — the realised goals-Δ CI half-width is **0.0697315** against an
ex-ante expectation of **0.072598364** (**0.9605×**). The battery therefore bought the precision it
was sized for; what it did not find is an effect at that size. Reading that fact is the
commander's, not this document's (#203).
