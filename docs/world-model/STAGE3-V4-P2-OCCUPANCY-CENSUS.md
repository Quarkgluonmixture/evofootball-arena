### 2.1 (a) THE INSTRUMENT — FORK-AND-HOLD (I4) ⭐

**The seam (zero `src/**`).** The hold uses `Match.forcedStation`
(`src/sim/Match.ts:626`; `src/ai/actionExecutor.ts:639–649`) — the C4-O2
**absolute-target** seam, `{ gid, target: V2, untilTick }`. It steers ONE
body toward a FIXED pitch point every tick, applied at the executor's read
BEFORE the onside/barred-box clamps (so the forced body gets no privilege
the world lacks), and is null in every production path. **This is the
correct seam for an OCCUPANCY census** (holding a rest-defence station means
staying deep near own goal REGARDLESS of where the ball goes) and is a
deliberate departure from the v1/v3 `forcedStationPolicy` seam
(`Match.ts:637`), whose ball-local offset is re-evaluated every tick — over
a `W_hold` of tens of seconds that seam would drag the body around chasing
the ball (a station-*tracking* census), not hold a station. The V3-P1
`forcedStationPolicy` machinery is NOT used; the lattice it defines IS
(below). ⭐ **FLAGGED interpretive choice — the seam.**

**The held candidate: RESOLVE-AND-FREEZE (#91).** For a fork on lattice
candidate `cand = {dx, dy}` at the fork tick `t_fork`, the held target is
computed ONCE, in the forced body's own attack frame, and FROZEN:

```text
target = { x: ball.pos.x + team.attackDir · cand.dx ,  y: ball.pos.y + cand.dy }   // at t_fork only
forcedStation = { gid, target, untilTick = t_fork + W_hold_ticks }                 // target CONSTANT for the window
```

This is exactly "a frozen region-class derived from the standing lattice"
(#91): the lattice supplies the spatial menu; resolving it once at `t_fork`
anchors it to the ball-and-own-goal geometry of the moment; freezing it
makes the body HOLD (occupy) that pitch cell for the window. **The incumbent
designation (the rest-defence assignment, `formationSpot`) enters the target
NOWHERE** (I8/#91). ⭐ **FLAGGED — resolve-and-freeze vs a moving ball-local
offset.**

**Which bodies are sampleable (the V3-P1 predicate heritage, restricted).**
The forced body is drawn by the V3-P1 rule (`stage3-v3-p1-role-census.ts:
435–441`): own-team (`side = owner.side`, §2.2), **non-GK**, **non-sent-off**,
**non-carrier** (`p !== owner`), and in the **STATION-FAMILY** action set
(`{MoveToFormationSpot, HoldPosition, SupportBallCarrier, MakeRun,
MarkOpponent}`), chosen by the same stable rotation (never proximity, never
role). One body per moment (unilaterality, I4).

**Hold enforcement + the honest interrupt classes (#49.3).** Each tick
`t ∈ [t_fork, untilTick)` the policy is re-asserted (the target constant;
the body re-steers by NORMAL LOCOMOTION, no teleport). The engine applies

records receipts (capped 1,000/class, first-N deterministic). The exception
families, inherited from V3-P1 (`:276–340`) and re-dispositioned for the

### 2.2 (b) BINDING-MOMENT SAMPLING — the own-possession face ⭐

**The predicate (V3-P1 sampling loop, restricted to own possession).** On
the census world, stepping full matches, a moment QUALIFIES iff:

```text
m.phase === 'playing'                          (open play)
&& m.ball.owner !== null                        (someone owns the ball)
&& m.simTime − lastMomentTime >= MOMENT_SPACING_S
&& side := owner.side                            (⭐ OWN-POSSESSION FACE ONLY — see below)
&& ∃ a sampleable body on `side` (§2.1 predicate: non-GK, non-carrier,
                                  non-sent-off, STATION-FAMILY action)
```

`lastMomentTime` advances on EVERY qualifying moment (the V3-P0/P1
placement). The forced body is the stable-rotation pick from the sampleable
pool (§2.1).

⭐ **FLAGGED — sampling is restricted to the OWN-POSSESSION face** (`side =
owner.side`), a deliberate departure from V3-P1's face-alternating rotation.
Reasoning: the hedge (rest defence) is a decision made WHILE ATTACKING —
P0b measured the rest-defence abandonment decisions IN SUPPORT (support-out
**0.298** [0.292, 0.304], route H) and the offside decisions in support
(0.364), i.e. own-possession moments. The delivery economy (the wide-held
channel) is likewise an attacking-phase phenomenon. Sampling the
opponent-possession face would price defensive shape (a different question)
and dilute power. The binding EVENT that turns an own-possession hold into a
concede-face cost is the **turnover** (51.335 turnovers/match banked, P0
§RESULT / #96.5(iii)); the hold persists through it (§2.1) and the outcome is
read over `W_long` spanning it. **Both OUTCOME faces are read on these
own-possession forks** (§2.4): opponent entries AGAINST (the price, gating)
and own entries FOR (the opportunity cost, labelled non-gating). This is
"read both faces", not "sample both faces".

**Spacing + budget (frozen).** ⭐ `MOMENT_SPACING_S = 4.0` (double V3-P1's
2.0 s — the long `W_long` makes each moment ≈ 19 forks × 30 s, so moments
are sampled sparsely). **No per-match moment cap** (a within-match cap would
bias toward early-match moments; matches are the cluster unit and `N`
(matches, capped at `N_max`) is the cost lever). The sizing smoke reports
realized qualifying/sampled moments per match and realized wall-cost per
moment (feasibility, §2.7). ⭐ **FLAGGED — spacing 4.0 s, no per-match cap.**

### 2.3 (c) THE HELD-CANDIDATE REGION CLASSES (#91; NEVER the incumbent designation) ⭐

Each fork holds a resolved-and-frozen lattice candidate (§2.1). The
**pricing bin** is a FROZEN region class computed on the RESOLVED target, in

```text
depthBand(target)   := localXBand(mine.localX(target.x))                     // reuses V3-P1 localXBand (:137–139)
                       ∈ { deep := own third (< −HALF_L/3),
                           mid  := middle third,
                           high := their third (> +HALF_L/3) }
lateralBand(target) := |target.y| ≤ HALF_W/2 ? 'central' : 'wide'            // pitch-symmetric split; folds L/R
regionClass         := depthBand × lateralBand                               // 6 classes
```

The **six frozen region classes**: `deep-central`, `deep-wide`, `mid-central`,
`mid-wide`, `high-central`, `high-wide`. Left/right are FOLDED by `|y|` (the
pitch is symmetric; a wide-left and a wide-right hold are one class — halving
the class count, doubling power). Reasoning for the axes: **depth** relative
to own goal is the rest-defence axis (`deep-*` = the rest-defence / hedge
channel; `high-*` = advanced support); **lateral** is the delivery axis
(`*-wide` = the crossing/cutback channel — the delivery economy grown; the

(#24: attainability — a 6-class × role × context grid is at the power
ceiling; the smoke reports which cells attain the floor). ⭐ **FLAGGED — the
region classes** (six, depth × lateral, folded L/R; the incumbent designation
appears nowhere).
