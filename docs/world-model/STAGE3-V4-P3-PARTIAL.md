## §1 — WHAT V4-P3-PARTIAL IS (and the one thing it measures)

CLASS H is spent. Two instrument generations (V4-P2 point-statue, V4-P2b
region-containment) triangulated the same shape and #109 banked the conclusion:
the long-horizon **discipline jobs are ASSIGNMENT-shaped** (team-level agreement —

But three of the four P3a-fired diseases are **NOT** CLASS H, and #110 mounts
their H-independent remedies as a **MEASUREMENT** (not a deployment attempt):

* **(J) THE IN-SUPPORT LAW** — the eye is consulted ONLY at moments inside the

## §2 — THE IN-SUPPORT LAW (remedy J) — frozen predicate, percept form, abstention classes, dormant seam

### 2.1 The law (generic, no named phase — I1)

> **The eye consults the table ONLY at a decision moment that satisfies the
> V3-P1 support predicate, evaluated PERCEPT-HONESTLY on the deciding body's own
> snapshot. At every other decision moment the incumbent machinery governs
> (holdIncumbent), and that is the eye choosing the incumbent.**

The V3-P1 support predicate (P0b §2.1, verbatim): a station-decision is IN SUPPORT
iff `phase === 'playing' && owner !== null` together with the eye-eligibility gate
already enforced in `src/ai/actionExecutor.ts` (`role !== 'GK'`, `!sentOff`,
`ball.owner !== p`, `action ∈ STATION_FAMILY`). By P0b's decomposition property,
at a decision moment the ONLY ways to be OUT of support are (1) `phase !==
'playing'` or (2) `ball.owner === null`. The law is **generic**: it names no
phase, zone or role; restart phases fall out of it ONLY because they fail clause
(1), and ball-in-flight moments ONLY because they fail clause (2) — exactly the
~46% extrapolation surface the exposure map measured (P0b §RESULT: 764,053 eye
decisions, out-of-support ≈ 0.4630/0.4604 per side; ~32% playing/in-flight +
~14% restart/loose; 122,677 + 122,939 in-flight, 53,101 + 52,924 restart-loose,
priced playing/owned cells out-of-support ≈ 0.0001).

### 2.2 The percept-honest form and its named abstention classes (I2)

The census evaluates the predicate on the TRUE match state. At CONSUMPTION the law
must be percept-honest (I2 / #110.4). The two clauses are handled distinctly:

* **Clause (2) ball-owned — PERCEPT-HONEST, the load-bearing clause.** Read from
  the deciding body's own pulled snapshot `match.perceivedSnapshot(p)`
  (`ObservedBall.ownerGid`, `ObservedBall.ageTicks`;
  `src/ai/perceptionSnapshot.ts`). IN SUPPORT (owned) requires a **FRESH LIVE
  perceived owner**: `snap.ball !== null && snap.ball.ownerGid !== null &&
  snap.ball.ageTicks ≤ SUPPORT_STALE_TICKS`. The named abstention classes (each a
  holdIncumbent, counted, receipted #49.3):
  * `E-OOS-UNSEEN` — `snap === null` or `snap.ball === null` (no ball percept).
  * `E-OOS-INFLIGHT` — `snap.ball.ownerGid === null` (perceived loose / in-flight).
  * `E-OOS-STALE` — a perceived owner but `ageTicks > SUPPORT_STALE_TICKS` (last
    saw it owned, but that is old): **a stale/unknown ball-state DEFERS TO THE
    INCUMBENT** (an executor operationalisation of #110.2(i) — "at
    out-of-support moments the incumbent machinery governs"; re-tagged at
    commander review, #111).

  ⚠ **FLAGGED — the in-support law reads the LIVE perceived owner, NOT the
  retained-owner ledger.** The v3 consumer's in-flight FACE repair
  (`perceivedContextV2`, `retainedOwnerGid`) manufactures a context during flight
  from the last-seen owner — precisely the mechanism that let the v3 eye consume
  the table in-flight (the 32% extrapolation). The in-support law **supersedes
  that repair for the support test**: support requires a fresh LIVE owner
  (`liveOwner !== null`), so an in-flight ball defers to the incumbent regardless
  of retention. This is the mechanism by which the in-flight extrapolation closes.
  Once in support, the live owner also gives the FACE directly, so the retained
  ledger is not consulted. (The retained-owner FACE repair stays available to the
  plain v3-eye attribution arm, §5, which runs the P3a consumer verbatim.)

* **Clause (1) phase === 'playing' — read as a PUBLIC signal.** ⚠ **FLAGGED
  interpretive choice.** `PerceptionSnapshot` carries no "perceived phase"
  channel; phase (a whistle) is a public game-state signal audible to all, not a
  hidden-body read, so the law reads `match.phase` directly. This is NOT truth by
  the back door (#8(l)): a restart whistle is not a concealed position. Its
  abstention class is `E-OOS-PHASE` (phase ≠ playing → holdIncumbent). If the
  commander prefers a fully perceptual phase read, the alternative is to gate on
  the perceived ball-state alone (clause 2) and let a restart's loose/in-flight
  ball fail clause (2) organically; both close the same cells (the exposure map's
  restart cells are ALL `ball = loose`, out-of-support either way). Frozen: read
  `match.phase` for clause (1); flagged for review.

`SUPPORT_STALE_TICKS` is a NEW pinned threshold (#48.4). ⚠ **FLAGGED — pinned
ex-ante, confirmed at the P3p-2 smoke.** Proposed default **30 ticks (0.5 s)** —
the freshness bound for "a fresh live owner"; the P3p-2 sizing smoke publishes the
perceived-owner `ageTicks` distribution and confirms the pin before the battery
(the census used age-0 truth, so the honest consumption analogue is "recently
observed"). No re-cut after sight; the smoke either confirms the pin or the stage
returns to the commander.

## §3 — THE TWO S BITS (context-key extensions) — geometry, staleness, the disjoint-scope rule, dormant seams

Both bits are binary context-key extensions of the V3-P1 cell `(context × role ×
candidate)`, both percept-honest with named abstention classes, both **PRICED**
through the targeted re-census (§4) and **never consumed unpriced** (I2/I3 —
#110.4). Each re-keys a cell by one bit; neither adds a gene, attribute or
percept channel (I8).

### 3.1 THE DELIVERY WIDE-OCCUPANCY BIT — `widthHeld ∈ {0, 1}` (a MOMENT property)

**Geometric definition (frozen).** `widthHeld = 1` iff, at the decision moment,
the deciding body PERCEIVES an own-side outfield teammate holding the wide
channel in the attacking half:

```text
widthHeld = 1  ⇔  ∃ q ∈ snap.players :
     q.side === observerSide  ∧  q.gid !== observerGid  ∧  q.gid % TEAM_SIZE !== 0 (non-GK)
   ∧ q.ageTicks ≤ WIDTH_STALE_TICKS                         (a FRESH observation)
   ∧ |q.pos.y| ≥ WIDE_EDGE                                  (in the wide channel)
   ∧ team.localX(q.pos.x) ≥ 0                               (in the attacking half)
```

⚠ **FLAGGED interpretive choices.** (i) **`WIDE_EDGE`** — proposed **`BOX_WIDTH /
2` = 14·GOAL_AND_BOX_SCALE ≈ 9.8 m** (a body wider than the penalty box is holding
the flank; `src/sim/constants.ts` BOX_WIDTH = 28·GOAL_AND_BOX_SCALE, HALF_W ≈
20.3, so this is ≈ 0.48·HALF_W). Alternative considered: `(2/3)·HALF_W`. The P3p-1
smoke publishes the delivery-origin lateral geometry and confirms the pin before
the census. (ii) **"attacking half"** = own-team-local x ≥ 0; alternative =
theirThird (`localX > HALF_L/3`); frozen at the half, flagged. (iii) The bit is a
**MOMENT property** (one value per decision moment, shared by all 18 candidates).

**Abstention (named, `E-ABSTAIN-WIDTH-STALE`).** The read is percept-honest: it
scans only FRESH observations (`ageTicks ≤ WIDTH_STALE_TICKS`). A false `widthHeld
= 0` could be a true absence OR a wide-blind spot. So: if the wide channel of the
attacking half carries **no fresh observation at all** (no own-side player
observed there within `WIDTH_STALE_TICKS`, whether or not one is present), the bit
is **UNKNOWN** and the consumer reads the v3 BASE (pooled-over-bit) cell — never a
guessed child (§4.3). If the wide channel IS freshly observed and empty,
`widthHeld = 0` is a genuine reading. `WIDTH_STALE_TICKS` pinned as
`SUPPORT_STALE_TICKS` (30 ticks) unless the P3p-1 smoke's age distribution says
otherwise; flagged, no re-cut after sight.

### 3.2 THE OFFSIDE BEYOND-LINE BIT — `beyondLine ∈ {0, 1}` (a per-CANDIDATE property)

**Perceived-line construction (frozen).** The perceived second-last-opponent line,
in observer-team-local x, built by the existing `offsideLineLocalX`
(`src/ai/formations.ts:466`) logic applied to the body's PERCEIVED opponents:

```text
perceivedLine = offsideLineLocalX-form over  { o ∈ snap.players :
                    o.side !== observerSide  ∧  o.ageTicks ≤ LINE_STALE_TICKS }
     i.e. the SECOND-LAST perceived opponent local-x (keeper counted),
     floored at the perceived ball-local-x and at 0 (no offside in one's own half).
```

For a candidate whose forced target is `(ball.x + attackDir·dx, ball.y + dy)`:

```text
beyondLine(cand) = 1  ⇔  team.localX(targetX(cand))  >  perceivedLine + OFFSIDE_EPS
```

⚠ **FLAGGED interpretive choices.** (i) The bit is a **per-CANDIDATE property**:
at one moment, a forward candidate may be beyond the line while a behind candidate
is onside — each fork's outcome lands in its own candidate's bit-child. This is
exactly the state-blindness the census mixes (P0b: "a run beyond the line and one
just onside share a cell"). (ii) `OFFSIDE_EPS` — the level-is-onside epsilon;
frozen at the sim's own offside-call epsilon (to be read from the offside
machinery at the P3p-0 build; flagged). (iii) The target is compared in
observer-team-local x, so `attackDir` and the fold are handled by `team.localX`
verbatim.

**Abstention (named, `E-ABSTAIN-LINE-STALE`).** The line needs ≥ 2 FRESH opponent
observations (the second-last is undefined otherwise). If fewer than two opponents
are freshly observed (`ageTicks ≤ LINE_STALE_TICKS`), or the relevant deep
defenders are stale, the line is **UNKNOWN** → the offside bit ABSTAINS for that
candidate → the consumer reads the v3 BASE cell for that candidate (§4.3).
`LINE_STALE_TICKS` pinned as `SUPPORT_STALE_TICKS` (30 ticks); flagged, confirmed
at the P3p-1 smoke.

### 3.3 ⚠⚠ FLAGGED (load-bearing) — THE DISJOINT-SCOPE RULE: each affected cell carries AT MOST ONE bit

The two bits' scopes overlap (both live in attacking own-possession contexts). A
cell keyed by BOTH bits would split 4 ways `(context × role × candidate × widthBit
× lineBit)`, quartering per-cell moments — power-hungry and unsupported by the
evidence (each contrast was measured as a single binary split: 45 delivery strata,
28 offside strata). **FROZEN:** each affected `(context × role × candidate)` cell
carries AT MOST ONE S bit, assigned by the pre-registered scope cut (§4.1) with a
fixed tie-break — **forward candidates in attacking contexts → the offside bit;
all other own-possession attacking cells → the delivery bit** — so every
re-censused cell is a clean BINARY split. The joint 4-way keying is considered and
REJECTED for power; recorded here as the design alternative. This is a significant
interpretive choice, surfaced for the commander.

### 3.4 The dormant `src/**` seams (SPECIFIED, not built)

Both bits are computed inside the same `stationEye !== null` block, flag-gated
`eye.v4?.deliveryBit === true` / `eye.v4?.offsideBit === true`; the extended-table
read replaces the plain `priceApproachesV3` lookup ONLY when a flag is on and the
cell is in scope, else the v3 cell is read byte-identically (X-OFF-IDENT). The
re-census probe (§4) reuses the V3-P1 instrument's fork machinery and computes the
same bits at the FORK moment. Same gates as §2.3.

### 4.3 THE MERGE RULE + SHA DISCIPLINE (frozen — flagged)

⚠ **FLAGGED — the merged table AUGMENTS, it does not overwrite; "replaced under
the extended key" means the CONSUMED key is extended while the v3 base cell is
RETAINED as the abstention anchor.**

```text
merged table  =  the committed v3 table (SHA 171a6dad…6559f)  ⊎  the bit-split children
                 for each affected (context × role × candidate) family, ONLY where the
                 relevant bit-child is in-power (n ≥ 150) at the re-census.
```

* **Unaffected families** — copied byte-identical from the v3 table.
* **Affected families** — the v3 base cell is RETAINED byte-identical, and up to
  two bit-children `(…× bit=0)`, `(…× bit=1)` are ADDED where each child is
  in-power. An under-powered child is dropped (publish-not-pool → the base governs
  those moments).
* **Consumption (§5):** for an affected cell the eye computes the bit
  percept-honestly. If the bit is READABLE **and** the matching child is in-power →
  it reads the child (the priced refinement). If the bit ABSTAINS (§3) **or** the
  matching child is under-powered → it reads the RETAINED v3 base cell (the coarser,
  still-certified value the v3 eye always read). A bit is therefore never consumed
  unpriced, and abstention never invents a value.

**SHA discipline (gate X-MERGE-IDENT, HARD).** (i) The projection of the merged
table onto the v3 base cells is byte-identical to the committed v3 table (canonical
`tableSha 171a6dad…6559f` reproduced over the base projection). (ii) For every
affected cell, the moment-count-weighted pool of its in-power children equals the
v3 base cell's own count decomposition (the split partitions the base cell's
moments exactly — the re-census's own X-form). (iii) The merged table is SHA'd and
quoted; the re-census output is twice byte-identical (X-DET). Any mismatch ⇒ FAIL,
STOP at the commander.
